# AI 辅助复盘规则

## AI 可以建议

- 想法升级
- 项目状态更新
- 缺失链接
- 长时间没有推进的项目
- 知识提炼
- 模板改进
- 规则改进
- 每周复盘草稿
- 项目会话后的知识沉淀提醒

## AI 不应该自动做

- 删除笔记
- 批量移动笔记
- 归档活跃项目
- 重写职业材料
- 未经确认创建新项目
- 未经确认迁移已有 repo
- 未经确认把跨项目知识写入 Jarvis

## 需要我确认

- 创建项目
- 归档项目
- 调整文件夹结构
- 修改规则
- 修改会影响未来流程的模板
- 修改简历或作品集
- 判断一次项目会话是否要沉淀到 repo 知识、Jarvis 复盘或 Jarvis 知识

## 公共可复用项目边界

当新增 skill、workflow、agent、plugin 或工具时，如果发现该能力具备以下任一特征，应建议新开会话作为独立公共项目推进：

- 可以发布到 GitHub 给别人使用
- 需要 README、LICENSE、安装说明或版本管理
- 需要独立 repo、测试、示例或发布流程
- 不只服务当前 Jarvis，而是可跨用户、跨项目复用
- 需要作为 Codex plugin、skill 包、MCP、CLI 或框架长期维护

当前会话只做判断、范围设计和新会话启动 prompt，不继续把完整公共项目塞进 Jarvis 内部目录。

新会话启动 prompt 至少包含：

- 项目目标
- 建议 repo 路径
- 第一版范围
- 目录结构
- 本地 Jarvis 接入方式
- 是否准备公开发布

## 提醒规则

AI 应该提醒，而不是默认执行。

一次有意义的项目会话结束后，AI 可以问：

```text
本次会话可能产生了值得沉淀的知识，要我准备一份知识沉淀草稿吗？
```

如果我确认，AI 可以在合适位置准备草稿：

- repo 内的 `docs`、`tasks`、`decisions`、`knowledge` 或 `reviews`
- Jarvis 的 `50_Reviews/Project Retros`
- 只有可复用的跨项目知识才进入 Jarvis 的 `40_Knowledge`

如果我拒绝，AI 不应该写知识沉淀文件。只有在我要求时，才可以在项目卡片里留下简短提醒。
