# 新想法分类流程

这个 workflow 用来处理所有新想法，不管它是不是代码项目。

## 目标

新想法先被捕获和分类，再决定是否进入创作、学习、项目、职业资产或长期知识。

## 输入

- 原始想法
- 来源
- 当前动机
- 是否想马上行动

## 分类维度

### 1. 生命周期

```text
Inbox -> Idea Briefs -> Incubation -> Promoted / Parked
```

### 2. 内容类型

从 [[../../30_Ideas/Categories/Categories|想法分类]] 中选择一个主分类：

- 应用 / 产品想法
- 音乐创作想法
- 内容创作想法
- 学习 / 研究想法
- 职业 / 作品集想法
- 生活 / 个人系统想法
- 商业 / 变现想法
- Jarvis 系统想法

## 判断问题

1. 这个想法主要想产生什么？
2. 最小下一步是什么？
3. 它需要代码、创作、研究、复盘，还是只是先停放？
4. 它是否和现有项目、作品、知识或职业资产有关？

## 输出

每个新想法至少给出：

- 生命周期位置
- 主分类
- 可选副分类
- 最小下一步
- 是否需要创建想法简报

## 升级路径

### 准备整理或执行

如果用户希望把想法整理成文档、判断能不能做，或准备实行方案，走 [[Idea Documentation and Capability Discovery|想法文档化与能力检索]]。

### 应用 / 产品想法

如果需要持续开发，走 [[Idea to Project|想法到项目]]。

### 音乐创作想法

如果是作品灵感，先产出 demo、歌词、参考曲或创作 brief，不强制进入 Workspace。

### 内容创作想法

如果是内容选题，先确定媒介、受众和最小发布形式。

### 学习 / 研究想法

如果可复用，最后沉淀到 [[../../40_Knowledge/Knowledge|Knowledge]]。

### 职业 / 作品集想法

如果能对外展示，连接到 [[../../20_Career/Career|Career]]。

### Jarvis 系统想法

如果会改变结构、agent、workflow 或规则，更新 [[../../90_System/System|System]] 和相关 registry。

## 固定提醒

分类时不要默认把所有想法都变成开发项目。

先问：

```text
这个想法更像代码项目、音乐创作、内容、学习研究、职业资产、生活系统，还是 Jarvis 系统改进？
```
